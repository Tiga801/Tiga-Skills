# 审校

站在**读者**的角度，只读中文，通读一份 Markdown 文档，找出读不通的句子，给出修改前后对比；用户确认后才改文件。判断交给你，替换交给 `$P`：本 skill 目录下的 `scripts/proofread.py`，用绝对路径以 `uv run $P …` 运行，用法写在脚本文件头。

## 第 1 步：准备

- 对象是一个 `.md` 文件。用户给的是目录或多个文件时，列出其中的 `.md`，请用户挑一个，然后停下。
- 读目标文件所在仓库的 `AGENTS.md` 和 `GLOSSARY.md`（有的话）。其中的写作规则和用语是审校标准的一部分，和本 skill 冲突时以项目为准。项目规定这个文件走别的审查流程（例如译文随核译审查）时，告诉用户改用那个流程，然后停下。
- 通读全文。

完成标准：确定了要审的文件，读过项目规则和全文。

## 第 2 步：找问题

逐段读，表格单元格、引用块和代码块里的中文注释都算在内；代码本身不审。只收下面这些**明确的问题**：

| 标签 | 是什么 | 例 |
|---|---|---|
| 语病 | 成分残缺或多余、搭配不当、主语错位、同义重复 | 「它们的能力上限受限于……」 |
| 误用 | 成语、比喻或术语用错 | 「以 bash 为最大公约数」「往往一针见血」 |
| 翻译腔 | 照搬英文的语序和结构，读着像译文 | 「Vim 针对这一分布做了彻底优化」 |
| 歧义 | 能读出另一种意思，或者会读错 | 「`rg` 默认忽略 `.gitignore`」（实为跳过其中列出的文件） |
| 过长 | 一句塞了三四层意思，难以断句 | |
| 术语 | 写法不符合项目规则，或同一概念用了几种叫法 | 「工作目录」「工作区」混用 |

读得懂、只是措辞还能更好的句子留给作者。改句保留原意和信息量，不增删内容，段落结构保持原样。

顺带发现的**事实疑点**（命令、参数、数据或说法与事实不符）单独列出，不写进改句：本地命令能验证的，运行后标「已验证」并写明怎么验证的；需要联网才能核实的标「未核实」，用户要求时再查。

完成标准：每一段都读过；每条问题都有标签、原文和改句。

## 第 3 步：出对比清单

在对话里输出，这一步不改文件。按文档章节分组、按原文顺序排列，每组放进一个代码块，原文照抄 Markdown 源码（反引号、`**` 原样保留）：

```
L24 ｜误用
原：……但写跨机器脚本时仍以 bash（或 POSIX sh）为最大公约数。
改：……但写需要跨机器运行的脚本时，仍应选兼容面最广的 bash（或 POSIX sh）。
```

- 行号写原文所在的行；长句和表格单元格只列改动的那一段，其余用「……」代替。
- 原因标签用第 2 步的标签，必要时补几个字说明。
- 清单末尾附「事实疑点」一节，逐条写行号、问题和核实情况。

**确认点**：请用户决定采纳哪些、跳过哪些、哪些改成别的写法，以及事实疑点要不要改、要不要联网核实。

完成标准：每一条都有了用户的决定（「全部采纳」也算）。

## 第 4 步：应用

1. 把清单的每一条写进意见文件 `<仓库根目录>/.tiga/proofread/<YYYY-MM-DD>/<目标文件在仓库里的相对路径>`，格式见「意见文件」，决定栏按用户的确认填；用户同意改的事实疑点也写成意见。`git check-ignore -q .tiga/x` 不通过（`.tiga/` 没被 git 忽略）时，先问用户放在哪。
2. 运行 `uv run $P check <目标文件> <意见文件>`，按报错修正意见文件，直到通过。
3. 运行 `uv run $P apply <目标文件> <意见文件>`。
4. 运行项目 `AGENTS.md` 里写的检查命令（如构建）。

完成标准：`apply` 成功；再跑一次 `check` 仍通过；项目检查通过，或已说明项目没有写检查命令。

## 第 5 步：汇报

- 改了多少条，跳过了哪些；
- 意见文件路径，以及可重跑的 `check` 命令；
- 项目检查的命令和结果；
- 还没核实的事实疑点。

不提交 git。

## 意见文件

```markdown
# 审校意见

- 目标：docs/computing/developer-tools/courses/missing-semester.md

## 01 误用

- 位置：L24 1.1 为什么需要 Shell
- 原文：但写跨机器脚本时仍以 bash（或 POSIX sh）为最大公约数。
- 建议：但写需要跨机器运行的脚本时，仍应选兼容面最广的 bash（或 POSIX sh）。
- 理由：「最大公约数」的比喻不贴切
- 决定：采纳
```

- 第一个 `##` 之前的内容随意，脚本不读。每条意见一个 `## 编号 标签` 标题，编号从 01 起按清单顺序编。
- 每个字段一行，写成 `- 字段：值`；位置、原文、建议、理由、决定五个字段都要有。
- **原文**：从目标文件逐字复制，标点、强调符号、行内代码原样保留，不加省略号；跨行时用 `⏎` 表示换行。它在文件里只能出现一次，不唯一就多复制几个字。
- **建议**：替换整段原文的文字，范围和原文相同。
- **决定**：`采纳`、`不改`、`改为：<文字>`，或留空（等于不改）。
- `- 状态：已应用` 由 `apply` 写在决定栏下一行，已应用的意见再次运行时跳过。
